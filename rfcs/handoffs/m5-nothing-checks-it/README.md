# Handoffs — M5: nothing checks it

Three units, one property: **a rule this project states and nothing verifies.**
No release — nothing here changes observable behaviour. This is M1's discipline
applied to the three places M3 found it missing.

Governed by RFC-016 (security, privacy and no-side-effects), with RFC-005,
RFC-013 and RFC-032 restating the same prohibition, and RFC-032 governing
encrypted-workbook handling. All in `done/`.

Keyed to the milestone rather than one RFC number, because the units belong to
different RFCs and no single one governs the set — the same deliberate departure
from RFC 000's `handoffs/NNN-slug/` convention that M4 made, noted here rather
than done silently.

## Queue

|---|---|---|---|
| 01 | [The prohibition nothing enforces](./01-stdout-prohibition.md) | RFC-016, RFC-005, RFC-013 | CI gate + record correction |

| 04 | [Close the bypass](./04-close-the-bypass.md) | RFC-016, RFC-005, RFC-013 | one lint attribute |

01 is merged. **04 must follow it** — it closes a bypass unit 01's own error
message advertises, and until it lands the gate stops an accident but not a
decision. 02 and 03 are independent of everything, in any order. 03 is the
largest, because the fixture does not exist and cannot be generated by
`rust_xlsxwriter`.

Unit 04 was not in the original set. It exists because unit 01's review found
that `#[allow(clippy::disallowed_macros)]` silently defeats the gate — and that
clippy prints instructions for doing so in the failure message itself. That is
**my scoping failure, not the implementer's**: unit 01 forbade touching `src/`,
and the fix is a crate-level attribute in `src/lib.rs`.

## Why M4 makes this the right milestone to follow with

M4 cleared eight statements that were false. The common shape was not
carelessness — every one of them was written by someone who believed it, and
every one survived because **nothing would have objected if it were wrong.**

`max_cells_compared` is the case to keep in mind. It was not merely undetected;
it was undetectable by anything we ran. Our gates were green throughout and
would have stayed green. What closed it was a person following a cause two lines
further than the defect they were fixing.

Every item in M5 is a rule currently in that state. The library must not write
to stdout — nothing objects if it does. Source paths must not leak — nothing
objects if they do. Encrypted workbooks must be detected as encrypted — nothing
objects if that stops working.

**None of these is currently violated.** `src/` is clean; the detection works.
This milestone is not remediation. It is making sure the next person to break
one of them hears about it from CI rather than from a consumer.

## Standing constraints

- **No behaviour change.** If a fix to `src/` becomes necessary to make a check
  pass, stop and report — that is a finding, not this milestone's work.
- **The fixture corpus must not move.** Unit 03 *adds* a fixture; it must not
  change any existing one. If a golden moves, stop and report.
- **A new dependency needs justification**, including a dev-dependency (RFC-026,
  RFC-035 `deny.toml`). Unit 03 may need one; it is the unit's job to argue for
  it, not to assume it.
- **Every check must be shown to fail when the rule is broken**, per RFC-036
  §5.1. A gate that passes on a clean tree proves nothing on its own — this is
  the milestone about checks that do not check, and it must not add one.
- Gates as always: fmt, clippy `-D warnings`, `deny`, MSRV 1.88, the full matrix.
