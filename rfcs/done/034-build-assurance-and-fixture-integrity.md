# RFC-034 — Build Assurance and Fixture Integrity

**Status.** Implemented (M1, 2026-08-15) — no release; M1 is internal quality work. All six acceptance criteria evidenced, each guard demonstrated both green and red.
**Target:** M1 (no release)
**Created:** 2026-08-15
**Related:** RFC-015, RFC-026, RFC-028, RFC-030, RFC-031, RFC 1.2/006

## 1. Summary

Establish the verification pipeline this project has never had: continuous
integration across the supported platforms and feature combinations, a fixture
harness that does not mutate the repository, and golden files that can actually
fail. Until this exists, no completion claim in this project carries evidence.

## 2. Motivation

The 2.2.3 architecture review found that:

- `.github/workflows/` is empty. There is **no CI**. The workflow was deleted in
  `a06fb0e` and never replaced, leaving NF-023 unmet.
- The `parallel` feature has **never compiled** — `src/diff.rs` references
  `ExecutionMode::Parallel`, which `src/options.rs` does not define. CHANGELOG
  2.2.0 documents it as shipped. Its only test is gated on the same feature, so
  it has never run.
- `cargo clippy --all-targets` **fails** (`approx_constant`, deny-by-default).
- `tests/gen.rs::generate_fixtures` is an ordinary `#[test]` that **writes into
  the source tree**. Every `cargo test` rewrites 14 tracked `.xlsx` files, which
  is the fixture byte-churn visible in every recent commit.
- **Nothing reads `expected.json`.** The seven committed golden files are
  write-only and provide zero regression detection, so RFC-015 and RFC-030 are
  simulated rather than implemented.
- The declared MSRV is verified by nothing.

Each of these is individually small. Together they mean the project cannot
distinguish "works" from "believed to work" — which is precisely how a
non-compiling feature reached a published release with documentation asserting
it worked.

## 3. Goals

- Every supported feature combination is built and tested on every change.
- A test run leaves the working tree byte-identical.
- Golden files are compared against and fail on unintended change.
- The declared MSRV is enforced rather than asserted.
- Static analysis is a gate, not advice.

## 4. Non-goals

- Coverage measurement or thresholds.
- Release automation or publishing (deferred; the previous release workflow was
  removed in `a06fb0e` and its replacement is out of scope here).
- Performance regression gating — RFC-027 owns that.
- Changing comparison behaviour of any kind.

## 5. Design

### 5.1 Fixture generation leaves the test harness

Generation moves from `tests/gen.rs` to `examples/gen-fixtures.rs`. Examples are
compiled by `cargo test --all-targets` but never executed, so generation becomes
explicit:

```sh
cargo run --example gen-fixtures --features serde
```

`tests/gen.rs` is deleted. Its assertions — which are genuine regression checks —
move into `tests/integration.rs` where they run against the committed fixtures
rather than against freshly generated bytes.

### 5.2 Fixtures become byte-reproducible

`rust_xlsxwriter` embeds a creation timestamp, which is why regeneration
produces different bytes each run. `DocProperties::set_creation_datetime` and
`Workbook::set_properties` pin it. The generator sets a fixed timestamp for
every fixture, so regeneration is idempotent and a diff in a `.xlsx` file means
a real change in the fixture's definition.

### 5.3 Golden files are asserted

A test walks `tests/fixtures/generated/*/`, compares `old.xlsx` against
`new.xlsx`, serialises the result, and asserts equality with `expected.json`.
It runs only under `--features serde`; without it the fixture pair is still
compared, and only the golden comparison is skipped.

Re-blessing is explicit and never automatic:

```sh
BLESS=1 cargo test --features serde -- goldens
```

A golden that changes without a corresponding intentional behaviour change is a
regression, and the diff in review is the evidence.

### 5.4 CI matrix

| Job | Covers |
|---|---|
| `test` | `{ubuntu, windows}` × `{--no-default-features, serde, chrono, cli, serde+chrono+cli}` |
| `msrv` | build at the declared `rust-version`, no dev-dependencies bypass |
| `lint` | `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` |
| `tree` | `cargo test` then assert `git status --porcelain` is empty |
| `fuzz-smoke` | each `fuzz/` target for a bounded number of runs (RFC-028) |

Windows satisfies NF-023's "Linux and one additional OS" and exercises the
platform-native path handling of NF-021.

The `tree` job is unusual but is the direct guard against §2's fixture
mutation: it makes tree cleanliness a build property rather than a convention.

### 5.5 Feature-combination coverage is the point

A matrix that builds every feature combination would have caught the `parallel`
break on the commit that introduced it. This is the single highest-value job in
the pipeline and must not be reduced to "default features only" for speed.

## 6. Interaction with the `parallel` feature

The matrix cannot go green while `parallel` exists in its current state. Its
removal (ROADMAP D2) is a prerequisite and is handled under RFC-025, not here.

## 7. Testing and verification

This RFC *is* verification infrastructure; its own acceptance is demonstrated by
the pipeline running green and by the deliberate-failure checks in the handoff —
a temporarily broken feature combination must fail the matrix, and a
temporarily altered golden must fail the golden job. An assurance pipeline that
has never been observed to fail has not been shown to work.

## 8. Alternatives considered

- **`xtask` for generation.** More conventional for larger projects, but adds a
  workspace member and build indirection for one generator. `examples/` achieves
  the same isolation at lower cost.
- **Keep generation as a `#[test]` guarded by an environment variable.** Fragile
  — the default path still risks writing, and the guard is invisible at the call
  site.
- **Drop the golden corpus.** Honest, but discards the regression protection
  RFC-015 and RFC-030 intend; the corpus is close to useful and only needs a
  reader.

## 9. Risks

- Byte-reproducibility depends on `rust_xlsxwriter` not embedding other
  nondeterministic content. If regeneration still differs after pinning the
  timestamp, fall back to treating committed `.xlsx` files as fixed inputs never
  regenerated in CI, and assert only on `expected.json`.
- A Windows runner may surface pre-existing platform assumptions. Those are
  findings, not reasons to drop the job.

## 10. Acceptance criteria

1. `cargo test` leaves `git status --porcelain` empty.
2. Every feature combination in §5.4 builds and tests green on both platforms.
3. `cargo clippy --all-targets -- -D warnings` passes.
4. A build at the declared MSRV passes.
5. Altering any `expected.json` causes a test failure.
6. Removing a variant from a feature-gated code path causes the matrix to fail.
