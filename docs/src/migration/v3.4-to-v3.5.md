# Migrating from 3.4.0 to 3.5.0

3.5.0 changes two things you may rely on, and corrects one instruction that was published
in 3.4.0 and earlier. Only the first needs a code change, and only if you keep the JSON
output or key a map by address.

## Every `CellDiff` now says which row each sheet numbers it in

`CellDiff` gained `row_placement: RowPlacement` in 3.5.0. It is a new field on a
`#[non_exhaustive]` struct, so existing code that reads the other fields compiles
unchanged.

**The JSON output gained a key on every cell diff**, and it is a tagged object, not
a string:

```json
"row_placement": { "PairedByAlignment": { "old_row": 2, "new_row": 3 } }
```

If you parse `--format json` or serialise `CellDiff` yourself, expect the new key. Nothing
is removed or renamed. `Deserialize` is not implemented, so a round trip is not supported.

Under the default `Positional` alignment every entry is `ComparedPositionally { row }`,
and `row` equals `address.row`.

## Do not collapse by address under an aligned mode

The `CellDiff` documentation before 3.4.0 told a consumer migrating from a per-facet
model to "collapse to one row per address". That is correct only under `Positional`.
Under `RowKey` or `RowSignature` one address can carry two entries that are distinct
changes, each numbered in a different sheet's row space. Collapsing by address merges
them and loses one.

**Keep the `cell_diffs` sequence as it arrives**, or key by `(address, row_placement)`:

```rust,no_run
use std::collections::HashMap;
use sheets_diff::{CellAddress, CellDiff, RowPlacement, WorkbookDiff};

fn changes_by_position(diff: &WorkbookDiff) -> HashMap<(CellAddress, RowPlacement), &CellDiff> {
    let mut out = HashMap::new();
    for sheet in &diff.sheets {
        for cell in &sheet.cell_diffs {
            out.insert((cell.address.clone(), cell.row_placement.clone()), cell);
        }
    }
    out
}
```

## Navigation: `next_after` and `previous_before` are deprecated

`DiffView::next_after` and `previous_before` find their argument by anchor equality. Under `RowKey` or
`RowSignature` two change rows can share an anchor, so they can fail to advance (`next_after`) or skip a change
(`previous_before`). Both are deprecated since 3.5.0 and keep their behaviour. Replace them with the key-based
route, which cannot do either:

```rust,no_run
use sheets_diff::output::view::{DiffView, ViewFilter};

# fn walk(diff: &sheets_diff::WorkbookDiff) {
let view = DiffView::new(diff);
let filter = ViewFilter::default();
let mut at = view.first_change(&filter);
while let Some(key) = at {
    // ... use the change at this key: view.change_at(view.position_of(&key, &filter).unwrap(), &filter)
    at = view.next_change(&key, &filter);
}
# }
```

A `ChangeKey` identifies a change within one `WorkbookDiff`. It is not an identity across two comparisons:
following "the same change" from one comparison to the next is an alignment question, and no key answers it.

`ChangeAnchor` is a sort position. Its `Ord` orders change rows into canonical sequence, and it is **not** an
identity. Do not key a `BTreeMap` by it: that compiles, and it silently merges rows that share an anchor.

## `RowSignature` with `sample_columns` set

3.4.0 fixed a changed cell going unreported in a row with no sampled cell. If you use `RowSignature` with
`sample_columns` set, re-check any result you trusted from that mode. A sheet affected by the defect now also carries
a `missing_row_signature` warning. A signature that repeats on either side also gets a `duplicate_row_signature`
warning, with the count per side: rows with identical content are paired in row order, so their pairing among
themselves is positional, and the sheet's confidence is at most `Medium`. Code that counts diagnostics per sheet
will see one more kind.
